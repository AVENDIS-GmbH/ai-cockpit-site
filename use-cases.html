Use cases

One pattern, many processes.

A pattern describes how an agent works. The first one is the document review: take a document, check it against a released ruleset, return structured data, let a person approve. A new process is that pattern with other knowledge.

Running today

Two processes, end to end.

Available

Legal pre-review of framework contracts

A contract and its annexes are checked from the contractor's point of view against 32 checkpoints in nine clusters, from liability to termination. The reviewer approves or returns; the report goes into the Word template.

Available

Curation of the rulesets

Proposals for new risk patterns and wording rules arrive as cases. The platform prepares each one — duplicates, pattern checks, current values — and a process owner accepts or rejects with a reason.

Learning loop

What reviewers learn flows back into the knowledge.

A finding in a review can become a proposal with one click. It is curated as its own case and, once accepted, is part of the next ruleset version — with the name of the person who approved it.

The same pattern fits

Other document checks.

These are not built yet. They need a ruleset, prompts and an output template — configuration, not a new product.

Further patterns

Added when a need does not fit — as a product decision.
