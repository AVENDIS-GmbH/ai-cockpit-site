Roadmap

Three stages, in this order.

Self-service is only affordable when the first stage has modelled every concept as data. That is why the order is not arbitrary. No dates are promised here.

Stage 1 · Today

Proof

One process end to end, every concept real.

  • Contract pre-review with a real on-premises model
  • Board and list for all processes
  • Review result, rounds, Word export
  • Rulesets with revisions and versions
  • Curation of proposals as a process
  • Audit trail, roles per area
  • Administration of users, areas and models
  • Process overview and settings
  • Token use per run, case and process
  • Delivery as containers, health endpoint
Stage 2 · Next

Breadth

Several processes, full administration.

  • More processes on the document review pattern
  • Administration of agents and data sources
  • A catalogue of preconfigured process templates
  • Dialogue-supported creation of cases
  • Single sign-on with an identity provider
  • Further roles, each seeing its own processes
Stage 3 · Later

Self-service

Customers set up their own processes.

  • Create a process in the interface
  • Set up and release its ruleset
  • Write review instructions and prompts
  • Define the input fields
  • Choose output template and model
  • Separation between tenants
  • Operation as a service
  • Usage and cost transparency

Noted for the future

The work you do with an AI assistant, as processes.

What people do one by one with an AI assistant today belongs on the platform as targeted processes and workflows: steerable and retrievable in parts, on whichever model is chosen, with an overview of usage and as auditable as every case. Not scheduled yet.

Chat with chosen knowledge

A dialogue page where you pick the knowledge bases to write with. The dialogue is a way into the platform, not its purpose: it runs on the chosen model and its use is recorded.

Skill management

Skills maintained in one place and exported in the formats of other tools, such as Claude Code and Open WebUI.

Any model

Processes, dialogues and skills run on the model you choose; the gateway stays the only connection to models.

Usage and audit across everything

One overview of usage per process, dialogue, skill and person, traceable like every case.

Deliberately not planned

No canvas for drawing arbitrary flows.

Free chaining is what a compliance officer fears. A bounded process that provably runs right is what they can answer for. Whoever needs free chaining is better served by an automation platform.

Operated for you — or by you

The regular case is operation by the provider, including the models. Operation in the customer's data centre stays possible with the same package.

The same artefact for both

That is a requirement, not a coincidence: a platform that only runs as a service loses its strongest argument with customers who keep their data in house.
