Features

What is in the product today.

Every screenshot shows the running application with its demo data. The interface is German.

Work

Board and list, one set of filters.

All cases live in one place. The board shows open cases in stage columns; the list adds finished ones and a status filter. Switching the view keeps what you filtered.

  • Drag a card, or use its menu — the keyboard path does the same
  • A moved card shows at once and returns if the server refuses
  • Filters live in the address, so a view can be passed on as a link

Review

A result you can check, not a text you have to trust.

The agent returns data, the platform renders it as a decision aid: first the result and what to do, grouped by action; the evidence quoted from the document, every checkpoint by cluster and wording issues fold open when you need them. The same data becomes a Word document in your template.

  • Rounds: a return with a comment starts the next run
  • Gaps of the agent are listed, not hidden
  • Each run shows its model, duration and token use

Knowledge

Rulesets that are maintained like documents.

Checkpoints, risk patterns and wording rules live in rulesets. Every change creates a new revision with author, time and reason; only released entries take effect.

  • Anyone can propose a rule from a finding
  • Proposals are curated as cases — who proposes does not decide
  • Accepting a proposal creates a new ruleset version

Governance

An audit trail for every case.

Which states, triggered by whom, when, with which reason. The trail is append-only: the database itself refuses to change or delete an entry.

  • Roles per area: operate, configure, administer
  • Who has no role in an area sees none of its cases
  • Transition rules are enforced on the server

Processes

An overview for everyone, settings for the owner.

Each process has a page that says what it does, which rulesets it checks against, which model it uses and what it consumed. Process owners change name, rulesets and model in the settings.

  • Processes appear in the navigation by themselves
  • Each role sees the processes of its areas
  • Token use of the last 30 days and in total

Models

The model is a choice, and the choice is visible.

Models are managed centrally and assigned per process, with defaults from platform and area. The process records on which models it was validated; an unvalidated model stays selectable, and the note travels into the result.

  • Where a model is operated is part of its record
  • Inactive models cannot be chosen
  • Every run stores the model it used

Operations

Built to be run by an operator, not by its developers.

One Compose file

Application, database and agent runtime. A few environment variables, then start.

Health endpoint

Reports database, agent runtime, document conversion and model gateway — so troubleshooting is not guessing.

Migrations at start

The image starts against an empty or an existing database. A second start overwrites nothing.

No secrets in the image

Credentials, endpoints and keys come from the environment only.

Versioned releases

The release pipeline tags images by version, never as a rolling “latest” — so you know what runs and can go back.

No cloud dependency

Nothing in the core needs an external service. Models run locally or in a region you choose.

One pattern, many processes.

Contract review is the first. The same pattern fits other document checks.
